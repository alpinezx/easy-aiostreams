Connecting
Warnings in the Caddy log after a restart? Usually fine.

The Hide noise button on the Caddy tab hides exactly the lines listed here, and shows how many it is hiding.

  • aborting with incomplete response on /api/logs/…: this page's live log connection closing, from switching tabs, leaving Logs or pressing Clear.
  • aborting with incomplete response ending in context canceled, on paths like /api/v1/dashboard/…/stream: a browser closed a live-updating page (the AIOStreams dashboard) while it was still sending. Reloading or leaving the page does it.
  • aborting with incomplete response ending in writing: … connection reset by peer (or broken pipe), on any path, including /api/v1/proxy/… video links: the player or browser on the other end hung up mid-transfer, which is what skipping, seeking or stopping playback does. "writing" always means the viewer's side. A reading: error is the AIOStreams side and is shown, except in the next case.
  • aborting with incomplete response ending in reading: … connection reset by peer or unexpected EOF, within 10 seconds of Caddy's own shutdown lines: a restart, update or restore stopped AIOStreams while someone was watching. With enough buffered, the viewer doesn't notice. The same error with no restart nearby is shown, since it means a stream broke.
  • aborting with incomplete response ending in unexpected EOF, on those same dashboard …/stream paths: AIOStreams restarted (or was updated) while the dashboard page was open, so its live connections were cut. The same error on any other path is not hidden.
  • dial tcp … :3000 connection refused, status 502, on those same dashboard …/stream paths: the open dashboard page trying to reconnect in the few seconds AIOStreams takes to start after a restart, update or restore. The same error on any other path is not hidden, since that can mean AIOStreams is down.
  • exiting; byeee!! and the shutdown lines: Caddy stopping for the restart.
  • Caddyfile input is not formatted, and HTTP/2 / HTTP/3 skipped on :80: shown on every start, and harmless.
  • dial tcp … :8080 connection refused: the panel itself restarting, so it can't be reached for a moment.
  • lookup aios-ui … server misbehaving, status 502: the panel container was stopped or being rebuilt while a browser tab was still open and asking it for updates.

Worth a look: tls or acme errors (certificate trouble), or dial tcp errors that keep repeating (a service Caddy can't reach).

Backup & Restore

Copy backups off this server. Each one holds your SECRET_KEY, your logins and, if you use one, your VPN private key, so keep them somewhere private.

Restoring rolls your AIOStreams setup back to one of these backups: AIOStreams and its configs, Caddy, the add-ons and this panel. Nothing else on the server changes. Restore checks it's safe to do from here first; Copy restore command is for doing it over SSH, or from the Terminal tab (then press Restart panel below afterwards).

Moving to a new server or a new domain is done over SSH on the new server, with sudo bash setup-aiostreams.sh restore <file>. See the backup guide.

Set aside by restores

Your setup as it was before a restore, kept so you could roll back. Delete it once the restored setup is working.

After a restore this panel keeps looking at the old folder until it restarts.
